# Паттерны общения с ИИ

Цель: пользователь пишет задачу одной строкой, а агент Cursor понимает её так, как понял бы
коллега после полугода совместной работы. Агент знает, из каких этапов у пользователя
состоит работа и что на каждом делает он сам, что подразумевает в короткой реплике, что уже
исправлял, как он оформляет задачи и страницы во внешних системах, когда его раздражают
вопросы и какой ответ он ждёт. Источник — прошлые чаты Cursor.

Работай автономно. Вопросов пользователю два: режим, если он не ясен из запроса, и одно
подтверждение перед записью правил. Остальные решения принимай сам в безопасную сторону
и называй в отчёте. Ничего не коммить и не пушь.

## Режимы

| Режим | Что разбирает | Когда лучше | Куда пишет |
|---|---|---|---|
| Все чаты | все чаты Cursor на этой машине | пользователь часто меняет папки, работает в разных доменах и на разных стеках. Правила получаются про человека, а не про проект | `~/.cursor/collab/user-rules.md` и тот же текст в отчёте для вставки в Customize → Rules → User Rules |
| Папка | чаты открытой папки, её подпапок и окон с несколькими папками | в папке живёт один проект со своим процессом, терминами и системами | `<корень>/.cursor/rules/collab/*.mdc` |

Режим бери из запроса: «по всем чатам», «общие правила», «везде» — все чаты; «для этого
проекта», «в этой папке» — папка. Если из запроса не понять, спроси одним вопросом
и покажи оба режима с колонкой «Когда лучше».

Режимы совмещаются: сначала «Все чаты» и вставить результат в User Rules, потом «Папка»
в отдельных проектах. Тогда в правила папки идёт только то, чего нет в User Rules.

Корень в режиме «Папка» — открытая в Cursor папка, если пользователь не назвал другую. Папка
скилла — та, где лежит этот `SKILL.md`. Пути к скриптам ниже считаются от неё.

## Состояние между запусками

Папка состояния: `~/.cursor/collab/` в режиме «Все чаты», `<корень>/.cursor/collab/`
в режиме «Папка». В ней:
- `state.json` — какие чаты уже разобраны. Повторный запуск разбирает только новые
  и изменившиеся;
- `findings.jsonl` — все находки прошлых запусков. Паттерн, который встретился один раз,
  в правила не попадает, но остаётся здесь и наберёт силу, если повторится;
- `decisions.tsv` — что пользователь принял и отклонил. Отклонённое не предлагается снова,
  пока не появятся новые диалоги с этим паттерном.

Чтобы разобрать всё заново, удали `state.json`.

## Шаги

### 1. Собрать диалоги

```bash
python3 -c "import tempfile; print(tempfile.mkdtemp(prefix='collab-'))"
python3 <папка скилла>/scripts/collect.py <рабочая папка> --all --state ~/.cursor/collab/state.json
python3 <папка скилла>/scripts/collect.py <рабочая папка> --root <корень> --state <корень>/.cursor/collab/state.json
```

Первая команда создаёт рабочую папку во временном каталоге, вторая — сбор для режима
«Все чаты», третья — для режима «Папка». На Windows вместо `python3` — `python`; если
Python не найден, скажи пользователю и остановись.

Скрипт читает чаты других папок в `~/.cursor/projects`. Если в настройках Cursor чтение
ограничено папкой проекта, команда упадёт в песочнице или Cursor попросит подтверждение:
перезапусти её с подтверждением и объясни пользователю, зачем это нужно.

Скрипт:
- читает чаты агента из `~/.cursor/projects/*/agent-transcripts/`;
- с `--root` берёт чаты самой папки, её подпапок и окон с несколькими папками: чат относится
  к корню, если пути в нём хотя бы наполовину ведут внутрь корня;
- пропускает чаты, которые не менялись с прошлого запуска;
- из реплики пользователя оставляет только текст запроса и помечает, что он приложил:
  файлы, выделенный код, вывод терминала, картинки;
- перед каждой репликой пишет, что агент делал: какие инструменты и сколько раз, какие
  команды запускал (только имя команды), какие скиллы прочитал, какие MCP-инструменты вызвал,
  что поручил субагентам. Следом — два последних ответа агента;
- для вызовов MCP, которые что-то создают или меняют, пишет строку `MCP-WRITE` с аргументами
  вызова до 1500 символов;
- отмечает `USER-ABORT`, когда пользователь остановил агента посреди хода;
- заменяет на `[секрет]` всё, что похоже на токен, пароль, ключ или строку подключения;
- пишет диалоги в `dialog/`, новое состояние в `state.json`, а в `summary.txt` — число
  диалогов по папкам, список диалогов по времени и группы файлов для субагентов.

Транскрипты субагентов скрипт не читает: в них нет реплик пользователя. Старые чаты, которые
Cursor хранил только в своей базе до появления `agent-transcripts`, тоже не попадут. Если
новых диалогов ноль, скажи об этом пользователю и остановись.

### 2. Прочитать действующие правила

В обоих режимах — User Rules из своего контекста и `~/.cursor/collab/user-rules.md`, если он
есть. В режиме «Папка» ещё `AGENTS.md` в корне и подпапках, все `.mdc` в `.cursor/rules`
и файлы правил других агентов, если есть. Это `{EXISTING_RULES}` для субагентов.

Потом получи известные ключи паттернов:

```bash
python3 <папка скилла>/scripts/aggregate.py <рабочая папка> --state-dir <папка состояния>
```

До разбора скрипт видит только находки прошлых запусков. `known-keys.txt` в рабочей папке —
это `{KNOWN_KEYS}` для субагентов.

### 3. Разобрать диалоги субагентами

Один субагент на группу из `summary.txt`, запуск — инструментом Task. Субагенту достаточно
чтения: если Task принимает `readonly: true`, ставь его. Промт —
[references/subagent-prompt.md](references/subagent-prompt.md) с подстановками. Субагент
возвращает результат текстом, а ты сохраняешь его в `<рабочая папка>/result-<номер группы>.md`.

Запускай субагентов несколькими вызовами Task в одном сообщении, чтобы они работали
параллельно, но не больше десяти за раз: в режиме «Все чаты» групп бывает несколько десятков,
их разбирай волнами. Если группа одна и меньше 40k символов, разбери её сам по тому же
промту. Если инструмента субагентов нет, разбирай группы сам по очереди.

### 4. Посчитать паттерны

Снова запусти `aggregate.py` той же командой, что в шаге 2. Он соберёт находки из
`result-*.md` и прошлых запусков, сгруппирует по ключу и запишет `patterns.md`:
у каждого паттерна сила, число диалогов и папок, сигналы, варианты правила, цитаты
и статус решения.

Сила:
- `strong` — пользователь сказал прямо, поправил записанное правило, или паттерн стоил ему
  итерации (поправка, прерывание, повтор) в двух диалогах и больше;
- `medium` — паттерн в двух диалогах и больше без явной оценки пользователя;
- `weak` — один диалог. В правила не идёт, ждёт повторения в `findings.jsonl`.

Если два ключа означают одно и то же, перезапусти `aggregate.py` с `--rename старый=новый`,
по одному на каждую пару. Переименование попадёт и в `findings.jsonl`, который потом уйдёт
в папку состояния.

### 5. Свести находки

По `patterns.md` и второй части ответов субагентов собери кандидатов в правила:
- первыми — паттерны с сигналом `violates`: правило уже есть, но не сработало. Их чинят
  формулировкой или местом в файле, а не новым пунктом;
- дальше `strong`, потом `medium`. `weak` и паттерны со статусом «отклонено» не предлагай.
  «Отклонено, но с тех пор новые диалоги» предложи снова и скажи, что изменилось;
- если у паттерна противоположные варианты правила, это противоречие: не выбирай сам,
  вынеси на подтверждение;
- паттерн из двух папок и больше — про человека, из одной — про этот проект. В режиме
  «Все чаты» правила про проект не пиши, а перечисли в отчёте как кандидатов для режима
  «Папка» с папками, где они встретились;
- если паттерн можно проверить механически — хуком Cursor, линтером, скриптом, — предложи это
  в отчёте вместо текста правила;
- если рабочий процесс пользователя — повторяющаяся цепочка шагов с понятным началом,
  предложи в отчёте оформить её отдельным скиллом.

### 6. Подтвердить

До записи покажи пользователю таблицу кандидатов: номер, тема, правило, сила, где применять
(User Rules или эта папка), одна цитата и число диалогов. Противоречия покажи отдельно,
с обоими вариантами. Задай один вопрос: записать всё, записать выбранные номера или ничего.
Если есть инструмент вопросов, задай его там.

### 7. Записать

Если в списке скиллов есть `write-for-humans`, прочитай его и следуй ему. Раскладка, лимиты
и формат пункта — [references/rules-template.md](references/rules-template.md). Записывай
только то, что пользователь подтвердил.

Потом обнови папку состояния, Cursor может попросить на это подтверждение:
- скопируй туда `state.json` и `findings.jsonl` из рабочей папки;
- допиши в `decisions.tsv` по строке на каждый показанный паттерн: ключ, `принято` или
  `отклонено`, число диалогов из `patterns.md`, дата. Разделитель — табуляция.

### 8. Закрыть от git

Только в режиме «Папка». Правила и состояние личные, команде они не нужны. Проверь, в git ли
корень: `git -C <корень> rev-parse --show-toplevel`. Если да — допиши `.cursor/rules/collab/`
и `.cursor/collab/` в `.git/info/exclude` этого репозитория. Это локальный gitignore,
коммитить его не нужно, а Cursor читает правила и из исключённой папки. Tracked `.gitignore`
не трогай. Если пользователь попросил отдать правила команде, `.cursor/rules/collab/`
не исключай и скажи об этом в отчёте.

### 9. Проверка завершения

Работа не закончена, пока не выполнено всё:
- `python3 <папка скилла>/scripts/check_rules.py <файл или папка правил>` — все строки `ok`.
  В режиме «Все чаты» это `~/.cursor/collab/user-rules.md`, в режиме «Папка» —
  `<корень>/.cursor/rules/collab`;
- в режиме «Папка», если корень в git: `git -C <корень> check-ignore -v
  .cursor/rules/collab/<любой файл>.mdc` показывает правило из `.git/info/exclude`;
- в папке состояния лежат свежие `state.json`, `findings.jsonl` и `decisions.tsv`;
- рабочая папка удалена: в ней выгрузки чатов.

### 10. Отчёт в чат

Первым — результат: режим, сколько диалогов разобрано и сколько пропущено как уже
разобранные, какие файлы созданы и где лежат, что проверено. Дальше:
- главное из анализа в 5–7 пунктах;
- в режиме «Все чаты» — полный текст `user-rules.md`, готовый к вставке в Customize → Rules →
  User Rules, и список кандидатов для режима «Папка»;
- в режиме «Папка» — блок «Для User Rules»: правила про человека одним текстом;
- агент не может записать User Rules сам: Cursor хранит их в настройках, а не в файле
  проекта. Скажи это и дай текст для вставки;
- предложения хуков, проверок и скиллов из шага 5;
- решения, принятые за пользователя;
- как проверить: открыть новый чат и спросить агента, какие правила он видит;
- блок «Не сделано».

В отчёте ссылайся на диалоги по id, без путей к транскриптам и без цитат с секретами.
