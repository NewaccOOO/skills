# Задача в Jira

## 1. Что собрать до черновика

Обязательно нужны:
1. Тип задачи (Story, Task, Bug и т. д.).
2. Эпик.
3. Связанные задачи, если они есть.
4. Данные для всех четырёх блоков описания (раздел 2).

Если что-то из этого не задано, спросить пользователя. Ничего не придумывать:
ни эпик, ни номера задач, ни ссылки, ни цифры, ни значения по умолчанию.
Вопросы задаются в чате и в текст задачи не попадают.

## 2. Состав задачи

Заголовок: глагол и объект, коротко и по сути.

Описание состоит ровно из четырёх блоков, других блоков нет:

1. **Контекст.** Зачем нужна задача и откуда она пришла (БТ, СТ, обращение).
2. **Что сделать.** Нумерованный список работ.
3. **Что не входит в задачу.** Явные границы, чтобы задачу не расширяли.
4. **Критерии готовности.** Нумерованный список. Каждый критерий — одно обычное
   предложение, которое можно проверить: что делаем и какой результат ждём.
   Без блоков «Дано / Когда / Тогда».

Блоков «Открытые вопросы», «Definition of Done», «Зависимости и ссылки» в описании нет.
Эпик и связи заполняются полями Jira.

Текст пишется по скиллу write-for-humans-ru.

## 3. Согласование и публикация

1. Черновик всегда сначала выводится пользователю в чат целиком: тип, эпик,
   связи, заголовок и описание.
2. Все правки пользователя принимаются. После каждой правки в чат выводится
   обновлённый черновик целиком.
3. Публиковать задачу в Jira можно только после чёткой прямой команды
   пользователя опубликовать именно этот черновик. Например: «публикуй»,
   «создавай задачу», «заводи в Jira».
4. Косвенные ответы командой не считаются: «ок», «норм», «выглядит хорошо»,
   «давай дальше», «да» на другой вопрос, одобрение отдельной правки, молчание.
   В этих случаях спросить: «Публикую этот черновик в Jira?»
5. Если после команды на публикацию черновик изменился, нужна новая команда.
6. После публикации сообщить номер и ссылку на созданную задачу. Если публикация
   не удалась, показать ошибку как есть и ничего не повторять без команды.
