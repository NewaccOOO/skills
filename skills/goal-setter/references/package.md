# Пакет спеки: состав, ID, критерии, гейты

## Размер пакета

Пакет лежит в `docs/specs/<slug>/` целевого репозитория, если пользователь не сказал иначе. Шаблоны — `assets/templates/`. Размер можно увеличить по ходу, уменьшать нельзя.

| Размер | Когда | Файлы |
|---|---|---|
| Quick | один проход, нет фаз и параллели, результат проверяется 1–5 гейтами | index, brief, requirements, GATES |
| Standard | работа дольше одного прохода или несколько независимых результатов | + research, tasks |
| Full | трудно откатить: архитектура, данные, прод, публичный API | + design, `adr/NNNN-<slug>.md` |

Если diff описывается одним предложением, пакет не нужен. Скажи это пользователю.

## ID и связи

Каждый факт живёт в одном документе, остальные ссылаются на его ID. Скрипт `scripts/check_trace.py` проверяет связи механически.

| Префикс | Что | Где определяется |
|---|---|---|
| G-n | цель | brief |
| NG-n | не-цель | brief |
| R-n | находка ресёрча | research |
| US-n | история или вопрос исследования | requirements |
| AC-n.m | критерий приёмки истории US-n | requirements |
| NFR-n | нефункциональное требование | requirements |
| C-n | ограничение | requirements |
| A-n | допущение | requirements |
| Q-n | уточнение из допроса | requirements, журнал |
| D-n | решение | design |
| ADR-NNNN | запись решения | adr/ |
| T-n | задача | tasks |

Как пишется определение: заголовок `### US-1: …` или пункт списка с жирным ID `- **AC-1.1** …`. Любое другое упоминание считается ссылкой. ID не переиспользуются. Отменённое не удаляй, а помечай «отменено: причина».

Скрипт считает ошибкой:

- ID определён дважды или ссылка ведёт на неопределённый ID;
- `AC-` или `NFR-` не упомянут ни в одном блоке задачи в tasks.md (упоминание в журнале не считается);
- у задачи `T-` нет ни одного `AC-` или `NFR-`;
- у `AC-` или `NFR-` нет гейта с тем же ID в GATES.md;
- остались `{{…}}` из шаблона или `[НУЖНО УТОЧНИТЬ`.

Предупреждает о размытых словах в brief и requirements и о задачах со ссылкой на `NG-`.

## Как писать критерии

Один критерий — одна проверяемая мысль и способ проверки.

- **Поведение** — шаблоны EARS: `THE SYSTEM SHALL …` (всегда), `WHEN событие THE SYSTEM SHALL …`, `WHILE состояние …`, `IF нежелательное условие THEN …`, `WHERE опция включена …`. Один триггер на критерий. Для сценариев подходит Given/When/Then в 3–5 шагов.
- **Ресёрч и аналитика** — критерий с числом и правилом подсчёта: «≥15 уникальных источников уровня A/B, у каждого ссылка и дата», «цифры сверены с выгрузкой X, расхождение ≤1%».
- **NFR** — число с единицей, источник числа и способ замера. Нет источника — это допущение `A-n`, а не требование.
- **Что не должно измениться** — отдельная история `US-0` с критериями `AC-0.m`.
- Без слов «удобно», «быстро», «эффективно», «по возможности», «при необходимости». Нужен порог или конкретика.
- «Качественно проработать» — не критерий. Разбей на то, что можно посчитать или проверить файлом.

## GATES.md

GATES.md — леджер unlazy в формате `~/.claude/skills/unlazy/templates/gates-leaf.md`, правила формата — `~/.claude/skills/unlazy/references/gates.md`.

- ID гейта совпадает с ID критерия: `- [ ] AC-1.1: …`, `- [ ] NFR-1: …`.
- Гейт `G0` проверяет сам пакет. Unlazy запускает команды гейтов из папки леджера, поэтому пути в `CHECK:` пиши от корня репозитория и запускай `gate-check` с `--cwd .` из корня.
- Команда проверки печатает маркер успеха только после всех проверок. Число из спеки не копируй в `EXPECT:` как доказательство самого себя: скрипт считает значение из источника.
- Ручной гейт (без `CHECK:`) — только когда ни одна команда не решает вопрос. Для ресёрча считать источники, секции и ссылки обычно можно небольшим скриптом.

```markdown
# Gates: {{название}}

Scope: {{один результат одним предложением}}

- [ ] G0: пакет спеки связан, гейты не пустышки
  CHECK: python3 ~/.claude/skills/goal-setter/scripts/check_trace.py --input docs/specs/<slug> && node ~/.claude/skills/unlazy/scripts/gate-lint.mjs docs/specs/<slug>/GATES.md
  EXPECT: LINT OK
  EVIDENCE: pending

- [ ] AC-1.1: CSV за период выгружается целиком
  CHECK: python3 scripts/verify_export.py --period 2026-08
  EXPECT: export verification passed
  EVIDENCE: pending
```

Скрипты проверок, которых ещё нет, — отдельная задача `T-` в tasks.md первой волны.

## Задачи

- Задача называет результат, а не активность: «эндпоинт выгрузки отдаёт CSV», а не «поработать над выгрузкой».
- Поля: `Требования`, `Зависит от`, `Файлы`, `Волна`. У задач одной волны множества файлов не пересекаются.
- Последняя задача — сквозная проверка: `--reverify` всего GATES.md и сверка отчёта с brief.
- Журнал исполнения внизу tasks.md заполняет исполнитель. Он заменяет отдельный worklog.

## Чеклист перед показом пользователю

- [ ] `check_trace.py` печатает `TRACE OK`, `gate-lint.mjs` — `LINT OK`.
- [ ] Каждый критерий проверяем без человека: число, файл, команда.
- [ ] Не-цели и границы автономии записаны явно, шага «спросить пользователя» в процессе нет.
- [ ] У каждого NFR есть источник числа и способ замера.
- [ ] Пакет самодостаточен: исполнитель стартует без этого разговора, файлы и интерфейсы названы.
- [ ] В Full есть альтернативы, откат и сигналы отката.
- [ ] Про каждую строку спросил себя: ошибётся ли исполнитель без неё? Если нет, строка удалена.
