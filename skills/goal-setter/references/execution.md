# Исполнение через unlazy

Постановка заканчивается согласованным пакетом. Исполнение идёт в свежей сессии по промту запуска: так контекст допроса не съедает внимание исполнителя.

## Перед запуском, вместе с пользователем

1. Покажи пользователю GATES.md: каждую команду `CHECK:` и скрипты, которые она вызывает.
2. После явного «да» одобри гейты из корня репозитория:

   ```bash
   node ~/.claude/skills/unlazy/scripts/gate-check.mjs --cwd . --approve docs/specs/<slug>/GATES.md
   ```

   Команда сразу прогонит проверки. Красные гейты на старте — норма, работа ещё не сделана. Одобрение привязано к пути леджера, `--cwd`, shell и `PATH`, поэтому исполнитель запускает проверки так же, из корня. Unlazy не даёт агенту одобрять унаследованные команды без человека, поэтому этот шаг нельзя пропустить.
3. Предложи один раз Stop-хук unlazy: он не даёт сессии закончиться, пока гейты красные, и отпускает после шести блоков без прогресса. Ставь только с согласия:

   ```bash
   node ~/.claude/skills/unlazy/scripts/install-hooks.mjs
   ```

4. Запиши статус «согласовано» и промт запуска в index.md.

## Промт запуска

```text
Ты автономный исполнитель. Используй скиллы goal-setter (режим исполнения, references/execution.md) и unlazy.
Пакет спеки: docs/specs/<slug>/. Прочитай index.md и все документы по порядку до первого действия. Выполняй буквально.
Готово только когда `gate-check.mjs --cwd . --reverify docs/specs/<slug>/GATES.md` печатает ALL MET и check_trace.py печатает TRACE OK.
Пользователя рядом нет: вопросы не задавай, решения фиксируй в журнале tasks.md. При конфликте побеждает спека.
Независимые задачи одной волны запускай субагентами одновременно.
```

## Режим исполнения

### Старт

- [ ] Прочитать index.md и документы в порядке таблицы.
- [ ] `check_trace.py --input docs/specs/<slug>` → TRACE OK. Не OK — сначала чинить пакет, код не трогать.
- [ ] `gate-check.mjs --status docs/specs/<slug>/GATES.md` — увидеть, что красное. `--status` ничего не запускает и не принимает `--cwd`.
- [ ] Выбрать режим из tasks.md: solo или параллельно.

### Solo

Задачи по порядку волн. Каждая задача проходит четыре прохода unlazy: сделать целиком → перечитать глазами эксперта и заменить дешёвые части → искать дефекты корректности и стыков → мелкая полировка до чистого прохода. После задачи прогнать гейты её критериев и дописать журнал.

### Параллельно

Оркестрованный режим unlazy (`~/.claude/skills/unlazy/references/orchestration.md` и `dispatch.md`), `<scope>` = `<slug>`. Источник плана — tasks.md, план не придумывается заново.

| tasks.md | `.unlazy/<slug>/PLAN.md` |
|---|---|
| `T-n` | лист `1.n`, леджер `gates/leaf-1.n.md` |
| Требования | гейты листа с теми же ID, только проверки его собственных файлов |
| Зависит от | `Needs` |
| Файлы | `Owns` и `OWNS:` в леджере листа |
| Волна | `Planned wave` |
| Контракт исполнения | раздел Contract |

Корневой `.unlazy/<slug>/GATES.md` содержит гейт, который перепроверяет приёмку пакета:

```markdown
- [ ] N0: приёмка пакета спеки
  CHECK: node ~/.claude/skills/unlazy/scripts/gate-check.mjs --cwd . --reverify docs/specs/<slug>/GATES.md
  EXPECT: ALL MET
  EVIDENCE: pending
```

Разрешено запускать несколько субагентов одновременно. Независимые задачи отправляй одной пачкой, не дожидаясь каждой: в одном сообщении несколько вызовов Agent в фоне. Последовательно выполняй только то, чему нужен результат предыдущей задачи. Перед запуском сверь `Файлы` задач волны, чтобы два агента не правили один файл, и сделай `--claim` для каждого листа.

Вернувшийся лист перепроверяй сам через `--reverify` его леджера. Отчёт субагента — не доказательство.

## Если спека разошлась с реальностью

Сначала правится спека, потом код.

- Новое или изменённое поведение: правка в requirements.md, запись в журнале tasks.md «Отклонения и находки», новый гейт в GATES.md, затем `check_trace.py`.
- Новый или изменённый `CHECK:` в GATES.md пакета одобрял пользователь. Исполнитель не одобряет его сам: добавь гейт и оставь `ABANDON: <id> нужно одобрение пользователя на новую проверку`, работу продолжай.
- Гейт невыполним в рамках спеки — `ABANDON: <id> <причина>`. Молча удалять гейт нельзя.
- Нарушить не-цель, чтобы закрыть критерий, нельзя. Это ABANDON с объяснением.

## Финиш

- [ ] `gate-check.mjs --cwd . --reverify docs/specs/<slug>/GATES.md`, в параллельном режиме — ещё `--scope <slug>`.
- [ ] `check_trace.py` → TRACE OK.
- [ ] Перечитать brief.md: цели `G-` достигнуты по сути, а не только формально, способы из раздела «Как выполнить формально без пользы» не использованы.
- [ ] Отчёт: сколько гейтов зелёных, красных и ABANDON, с ID вида `GATES:AC-1.2`; отклонения из журнала; что проверить руками.
- [ ] Статус в index.md: «готово» только при ALL MET. Есть ABANDON или красные гейты — «передано с долгом», и это прямо написано в отчёте.
