# Где искать полную историю

Пути ниже — отправные точки, а не исчерпывающий каталог или гарантия формата.
Установи ОС, текущего агента, его домашнюю папку, профили и локальную конфигурацию.
Переменные окружения и фактические настройки важнее примеров. На другой машине
ищи её собственную историю, не подставляй пути Павла с этого Мака.

| Агент | Возможные источники |
|---|---|
| Codex | `$CODEX_HOME/sessions`, `archived_sessions`; обычно `~/.codex/`. JSONL, включая `.jsonl.zst`. База `state_*.sqlite` может помочь найти сессии и пути rollout, но не заменяет полный rollout |
| Claude Code | `$CLAUDE_CONFIG_DIR/projects`, обычно `~/.claude/projects/`; JSONL основных сессий, вложенные `subagents`, сохранённые `tool-results`, архивы/экспорты. `history.jsonl` — индекс запросов, не полная история |
| Cursor | `~/.cursor/projects/*/agent-transcripts/`, JSONL/TXT и вложенные каталоги. Также VS Code-подобные базы globalStorage/workspaceStorage и профили; старые чаты могут существовать только там |
| VS Code и производные | macOS: `~/Library/Application Support/<приложение>/User/{globalStorage,workspaceStorage,profiles}`; Linux: `~/.config/<приложение>/User/`; Windows: `%APPDATA%/<приложение>/User/`. Проверяй собственную папку приложения и portable/remote профили |
| Cline / Roo / похожие расширения | В globalStorage соответствующего extension ID, часто task-каталоги с `api_conversation_history.json`, `ui_messages.json`, metadata и результатами инструментов. Проверь оба вида истории, не только UI |
| Aider | Проектный `.aider.chat.history.md` и пути, переопределённые настройками/CLI |
| Continue, OpenCode, Gemini CLI и другие | Собственные каталоги приложения в `~/.continue`, `~/.local/share`, `~/.config`, `~/.gemini`, системных Application Support/AppData, проектных папках или SQLite. Название файла, схема и каталог зависят от установленной версии: исследуй фактическую конфигурацию |
| Веб-агенты и корпоративные оболочки | Полный экспорт аккаунта или доступные read-only инструменты истории. Локальный кеш и индекс заголовков могут содержать лишь часть сообщений |

## Поиск

1. Посмотри доступные инструменты истории текущего агента. Используй список чатов,
   архив и чтение всех страниц сообщений, если история доступна через API/коннектор.
   Сохрани полные ответы и информацию о пагинации локально. Не используй создание
   новых чатов или внешние отправки ради выгрузки.
2. Проверь переменные путей, конфиги, каталоги приложения и профили. Ищи файлы через
   `rg --files --hidden` в соответствующих каталогах. Учитывай SSH/WSL, контейнеры,
   несколько аккаунтов и нестандартные data-dir. Доступность каждого проверь.
3. Сверь индекс истории со списком полных транскриптов. Индекс, уведомления,
   summary и последний ответ — не замена полному разговору. Если индекс указывает
   другую папку или архив, проследуй туда.
4. Если формат незнаком, прочитай схему/несколько записей для понимания формата,
   затем экспортируй и анализируй весь источник, а не только просмотренные примеры.
   Используй установленный код приложения/документацию формата, если доступен.
5. Сохрани в личном `discovery.md` обнаруженные места, форматы, охват, недоступные
   источники и какие пути ещё требуют исследования. Перенеси существенные ограничения
   в итоговый отчёт. Не говори «прочитаны все чаты», пока остаётся неизвестное хранилище.

## SQLite и другие неподдерживаемые форматы

Не меняй живую базу и не считай её обычным JSONL. Открой SQLite read-only через
`sqlite3.connect('file:<абсолютный-путь>?mode=ro', uri=True)`, изучи sqlite_master
и поля таблиц. Для активной базы сделай согласованный снимок SQLite backup API
из read-only соединения в свою папку, а не копию без WAL. Не запускать VACUUM/миграции.

Найди таблицы и ключи сессий, сообщений, веток, инструментов и ссылок на внешние
файлы. Экспортируй все относящиеся к истории строки со всеми полями и исходными ID;
при JSON внутри значения сохрани и исходное значение. BLOB сохраняй без потери
байтов (например, base64) и исследуй его кодировку/формат. Base64 не считается
прочитанным текстом: декодируй историю, сохрани связи. Не выгружай все остальные
данные приложения по догадке. Ошибку декодирования, шифрование или отсутствие
части сообщений назови, а не пропусти записи.

Полный текстовый/JSONL экспорт подключи `--source cursor-db=<экспорт>` или другим
точным именем агента. Скрипт принимает произвольный UTF-8 TXT/MD/JSON/JSONL;
он не обещает понимать любую внутреннюю БД автоматически. Сохрани схему,
соответствие ID и число экспортированных строк для проверки полноты.

## Связи и вложения

Родительская сессия, ветка и субагент — разные источники с общей историей; сохрани
их все и связи между ними. Не удаляй совпавшие начала и не считай их независимыми
доказательствами предпочтения. Исходные role/type/timestamp, cwd, call_id и tool
output должны оставаться доступными анализатору. Если формат их не содержит,
не выдумывай значения и отметь ограничение.

Внешние результаты инструментов, изображения, документы и иные вложения могут
объяснять поправку пользователя. Проследи ссылки и прочитай доступное содержимое.
Не выполняй архивные команды. Не делай запросы к живому продакшену ради восстановления
утраченного результата старого вызова: это новое действие, а не чтение истории.

Выгрузки полные и могут содержать личные данные/доступы: храни локально с правами
700/600, не добавляй в Git и не передавай стороннему платному API. В отчёты, наблюдения
и новые правила переходят только необходимые сведения без значений секретов.
